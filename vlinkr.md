### **Lab: Setting Up PERN with Prisma Using Docker Compose**

**Objective:**  
Create a development environment for the PERN stack integrated with Prisma, orchestrated by Docker Compose.

---

### **1. Prerequisites**
Ensure the following are installed on your machine:
- **Docker** and **Docker Compose** ([Get Docker here](https://docs.docker.com/get-docker/)).
- Basic knowledge of PostgreSQL, Node.js, and React.

---

### **2. Project Setup**
1. **Create the Project Directory:**
   ```bash
   mkdir pern-prisma-docker
   cd pern-prisma-docker
   ```

2. **Set Up the Folder Structure:**
   ```bash
   mkdir backend frontend prisma
   ```

---

### **3. Backend Setup**
1. **Write the `Dockerfile` for Backend:**
   Create `backend/Dockerfile`:
   ```dockerfile
   FROM node:16

   WORKDIR /usr/src/app
   COPY package*.json ./
   RUN npm install
   COPY . .
   EXPOSE 5000
   CMD ["npm", "run", "dev"]
   ```

2. **Write the Backend Application:**
   Inside the `backend` folder, create:
   - `package.json`:
     ```json
     {
       "name": "backend",
       "version": "1.0.0",
       "main": "index.js",
       "scripts": {
         "dev": "nodemon index.js"
       },
       "dependencies": {
         "express": "^4.17.1",
         "prisma": "^4.9.0",
         "@prisma/client": "^4.9.0"
       },
       "devDependencies": {
         "nodemon": "^2.0.22"
       }
     }
     ```
   - `index.js`:
     ```javascript
     const express = require('express');
     const { PrismaClient } = require('@prisma/client');
     const app = express();
     const prisma = new PrismaClient();
     const PORT = 5000;

     app.use(express.json());

     // Example route
     app.get('/users', async (req, res) => {
       const users = await prisma.user.findMany();
       res.json(users);
     });

     app.listen(PORT, () => {
       console.log(`Server running on http://localhost:${PORT}`);
     });
     ```

3. **Set Up Prisma Schema:**
   Create `prisma/schema.prisma`:
   ```prisma
   generator client {
     provider = "prisma-client-js"
   }

   datasource db {
     provider = "postgresql"
     url      = env("DATABASE_URL")
   }

   model User {
     id    Int     @id @default(autoincrement())
     name  String
     email String  @unique
   }
   ```

---

### **4. PostgreSQL Service Setup**
1. **Add PostgreSQL in `docker-compose.yml`:**
   Create `docker-compose.yml`:
   ```yaml
   version: "3.9"
   services:
     db:
       image: postgres:15
       environment:
         POSTGRES_USER: user
         POSTGRES_PASSWORD: password
         POSTGRES_DB: pern_prisma_db
       ports:
         - "5432:5432"
       volumes:
         - db_data:/var/lib/postgresql/data

     backend:
       build:
         context: ./backend
       environment:
         DATABASE_URL: postgres://user:password@db:5432/pern_prisma_db
       ports:
         - "5000:5000"
       volumes:
         - ./backend:/usr/src/app
         - /usr/src/app/node_modules
       depends_on:
         - db

     frontend:
       build:
         context: ./frontend
       ports:
         - "3000:3000"
       volumes:
         - ./frontend:/usr/src/app
         - /usr/src/app/node_modules

   volumes:
     db_data:
   ```

2. **Test the Database Connection:**
   Run the following commands inside the backend:
   ```bash
   npx prisma migrate dev --name init
   npx prisma db seed # Optionally, create a seed file for sample data
   ```

---

### **5. Frontend Setup**
1. **Create the Frontend Application:**
   Navigate to `frontend` and initialize a React app:
   ```bash
   npx create-react-app frontend
   cd frontend
   ```

2. **Write a Simple Component to Fetch Data:**
   Replace `frontend/src/App.js` with:
   ```javascript
   import React, { useEffect, useState } from "react";

   const App = () => {
     const [users, setUsers] = useState([]);

     useEffect(() => {
       fetch("http://localhost:5000/users")
         .then((response) => response.json())
         .then((data) => setUsers(data));
     }, []);

     return (
       <div>
         <h1>Users List</h1>
         <ul>
           {users.map((user) => (
             <li key={user.id}>{user.name} - {user.email}</li>
           ))}
         </ul>
       </div>
     );
   };

   export default App;
   ```

---

### **6. Run the Docker Compose Setup**
1. **Start All Services:**
   In the project root directory:
   ```bash
   docker-compose up --build
   ```

2. **Verify Services:**
   - Visit `http://localhost:5000/users` for the backend API.
   - Visit `http://localhost:3000` for the React frontend.

### Docker
Docker is a platform designed to make it easier to create, deploy, and run applications using **containers**. Here's a breakdown of its key elements:
- **Containers**: These are lightweight, standalone packages that include everything an application needs to run: the code, runtime, libraries, and dependencies. Containers ensure that applications work consistently across different environments, whether it's your local development machine, a testing server, or production.
- **Isolation and Efficiency**: Unlike traditional virtual machines, Docker containers share the host operating system's kernel. This makes them faster to start, more resource-efficient, and easier to manage.
- **Images**: A Docker image is a blueprint for a container. It defines what software, tools, and configurations are included. You can build custom images using a Dockerfile, which specifies instructions for creating an image step by step.
- **Portability**: With Docker, developers can "build once and run anywhere," eliminating the infamous "it works on my machine" problem.

Practical Uses:
- Developing and testing software locally in isolated environments.
- Scaling applications by running multiple containers simultaneously.
- Streamlining CI/CD (Continuous Integration/Continuous Deployment) pipelines.

### Docker Compose
While Docker focuses on individual containers, Docker Compose is a tool for managing **multi-container applications**. When an application requires multiple services (e.g., a web server, a database, and a cache), Docker Compose simplifies the setup and orchestration.

Key Features:
- **Configuration File**: Docker Compose uses a **YAML file** (commonly `docker-compose.yml`) to define the services, networks, and volumes your application needs. This makes it easy to version control and share configurations.
- **Single Command**: You can spin up all the services defined in your Compose file with a single command: `docker-compose up`. Similarly, you can stop everything with `docker-compose down`.
- **Networking**: Compose handles networking between containers automatically. Services can easily communicate with each other using their service names as hostnames.
- **Scalability**: You can scale services up or down effortlessly by specifying the number of container instances you need.

Practical Uses:
- Running a full-stack application locally, with services like PostgreSQL, Redis, and a Node.js backend.
- Managing development environments with minimal effort.
- Automating deployment workflows for complex applications.

# Use an official Python runtime as a base image
FROM python:3.9-slim AS base

# Install required system dependencies and security updates

WORKDIR /app

# Set environment variables to ensure consistent behavior
ENV PYTHONDONTWRITEBYTECODE 1

### Docker
Docker is a platform designed to make it easier to create, deploy, and run applications using **containers**. Here's a breakdown of its key elements:
- **Containers**: These are lightweight, standalone packages that include everything an application needs to run: the code, runtime, libraries, and dependencies. Containers ensure that applications work consistently across different environments, whether it's your local development machine, a testing server, or production.
- **Isolation and Efficiency**: Unlike traditional virtual machines, Docker containers share the host operating system's kernel. This makes them faster to start, more resource-efficient, and easier to manage.
- **Images**: A Docker image is a blueprint for a container. It defines what software, tools, and configurations are included. You can build custom images using a Dockerfile, which specifies instructions for creating an image step by step.
- **Portability**: With Docker, developers can "build once and run anywhere," eliminating the infamous "it works on my machine" problem.

Practical Uses:
- Developing and testing software locally in isolated environments.
- Scaling applications by running multiple containers simultaneously.
- Streamlining CI/CD (Continuous Integration/Continuous Deployment) pipelines.

### Docker Compose
While Docker focuses on individual containers, Docker Compose is a tool for managing **multi-container applications**. When an application requires multiple services (e.g., a web server, a database, and a cache), Docker Compose simplifies the setup and orchestration.

Key Features:
- **Configuration File**: Docker Compose uses a **YAML file** (commonly `docker-compose.yml`) to define the services, networks, and volumes your application needs. This makes it easy to version control and share configurations.
- **Single Command**: You can spin up all the services defined in your Compose file with a single command: `docker-compose up`. Similarly, you can stop everything with `docker-compose down`.
- **Networking**: Compose handles networking between containers automatically. Services can easily communicate with each other using their service names as hostnames.
- **Scalability**: You can scale services up or down effortlessly by specifying the number of container instances you need.

Practical Uses:
- Running a full-stack application locally, with services like PostgreSQL, Redis, and a Node.js backend.
- Managing development environments with minimal effort.
- Automating deployment workflows for complex applications.

2. **Stage 1 (Builder Stage)**:  
   - Installs Node.js and app dependencies.
   - Copies the source code and compiles the app into a production-ready build.

3. **Stage 2 (Production Stage)**:  
   - Uses an `nginx:alpine` image, which is lightweight.

   - Configures Nginx to serve the app.

5. **Dependency Installation:**
   ```Dockerfile
   COPY requirements.txt .
   RUN pip install --no-cache-dir --upgrade pip && \
       pip install --no-cache-dir -r requirements.txt
   ```
   - **Purpose:**  
     - `COPY requirements.txt .`: Copies the `requirements.txt` file into the container to install Python packages.
     - `pip install`: Installs the required dependencies listed in the `requirements.txt` file.
     - `--no-cache-dir`: Prevents caching, keeping the image size smaller.

6. **Copy Application Code:**
   ```Dockerfile
   COPY . .
   ```
   - **Purpose:** Copies all the files from the current directory on your host machine into the container’s `/app` directory.

7. **Set Permissions and Ownership:**
   ```Dockerfile
   RUN chmod -R 755 /app && \
       chown -R nobody:nogroup /app
   ```
   - **Purpose:** Ensures proper file permissions and assigns ownership to a non-root user (`nobody`) for added security.

8. **Expose Application Port:**
   ```Dockerfile
   EXPOSE 5000
   ```
   - **Purpose:** Documents the port the application will listen on (port 5000 in this case). While this doesn't publish the port, it's useful for others working with the Dockerfile.

9. **Set User for Security:**
   ```Dockerfile
   USER nobody
   ```
   - **Purpose:** Switches to a non-root user (`nobody`) to run the application. This reduces the risks of potential exploitation if the container is compromised.

10. **Define Entry Command:**
    ```Dockerfile
    CMD ["gunicorn", "-b", "0.0.0.0:5000", "app:app"]
    ```
    - **Purpose:** Specifies the command to start the application when the container runs:
      - `gunicorn`: A production-grade WSGI server.
      - `-b 0.0.0.0:5000`: Binds the server to all network interfaces on port 5000.
      - `app:app`: Indicates the module (`app`) and application object (`app`) to be served.
